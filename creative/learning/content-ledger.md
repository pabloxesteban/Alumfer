# Content Ledger — Registro de ADN Creativo vs. Resultado

> El corazón del autoaprendizaje.
> Una fila por pieza publicada. Vincula lo que decidimos con lo que pasó. Sin este registro, el sistema no puede aprender de sí mismo.

---

## Por qué un "ledger"

Cada pieza es un experimento. El ledger es el cuaderno de laboratorio: registra las variables (el ADN creativo) y el resultado. Con suficientes filas, aparecen correlaciones: qué hooks retienen, qué ángulos generan DMs, qué emociones se guardan. Esas correlaciones alimentan `feedback-loop.md`.

## Esquema de una entrada

```
─────────────────────────────────────────────────────────────
PIEZA: [slug]                              FECHA PUB: [YYYY-MM-DD]
FORMATO: [reel / carrusel / historia / foto]   DURACIÓN: [seg, si video]

── ADN CREATIVO (lo que decidimos) ──
HOOK:        "[texto exacto]"    TIPO: [de los 16]
ÁNGULO:      [de knowledge/angles/]
ESTRUCTURA:  [de knowledge/storytelling/]
TEMA:        [DVH / portón / proceso / temporada / ...]
EMOCIÓN:     [la dominante fijada por el Strategist]
COPYWRITER:  [especialista usado]
CTA:         [qué se pidió y cómo]
SCORE PREDICHO: [XX/100]  (del Viral Reviewer)

── RESULTADO REAL (lo que pasó) ──
RETENCIÓN 3s:  [%]        (¿frenó el scroll?)
GUARDADOS:     [n / % alcance]   (intención futura — señal fuerte Alumfer)
COMPARTIDOS:   [n]        (el contenido viajó)
COMENTARIOS:   [n + calidad: sustancia / vanidad]
DMs / CONSULTAS: [n]      (señal primaria — intención de compra)
ALCANCE:       [n]        (contexto, no objetivo)

── APRENDIZAJE ──
PREDICCIÓN vs REAL: [acertamos / sobreestimamos / subestimamos]
FACTOR QUE ENGAÑÓ:  [si el score falló, cuál factor]
LECCIÓN:            [qué se aprende]
ACCIÓN:             [regla creada/degradada · peso recalibrado · perfil ajustado]
→ REFLEJADO EN:     [archivo de knowledge/ o engine/ que se actualizó]
─────────────────────────────────────────────────────────────
```

## Métricas y su peso para Alumfer

Orden de importancia (de `engine/north-star-metric.md`):

```
1. DMs / consultas WhatsApp   → intención de compra (lo que importa)
2. Retención primeros 3s      → ¿el hook funcionó?
3. Guardados                  → intención diferida (el cliente decide en semanas)
4. Compartidos                → alcance orgánico de calidad
5. Comentarios con sustancia  → resonancia real (no "lindo 👍")
—  Likes / follows            → vanidad, se registran pero no deciden
```

## Cómo se completa una entrada

1. **Al publicar:** se cargan los campos de ADN creativo (ya conocidos del paquete del Orchestrator) y el score predicho.
2. **A las 48–72h:** se cargan las señales tempranas (retención, guardados, DMs). La ventana de 48–72h captura el pico de consultas de Alumfer (`analytics/success-patterns.md` P4).
3. **A las 2–4 semanas:** se revisan las consultas diferidas (el cliente educativo llega tarde).
4. **Se completa el aprendizaje** y se dispara la acción vía `feedback-loop.md`.

## Estado inicial
Vacío. Se llena con cada publicación. La primera decena de filas es exploratoria (poca base estadística); a partir de ahí las correlaciones empiezan a ser confiables y las reglas de `creative-rules/` a moverse.

## Regla
Una pieza sin fila en el ledger es una pieza de la que no aprendimos nada. El registro no es opcional: es la condición para que el engine mejore.
